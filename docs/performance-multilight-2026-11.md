# 多灯描画・照度計算の追加軽量化

2026-11-11。比較前は `4c7fa85a785d43b5d15ca5a7ac6b0692614442c0`。

多数の照明で重複していた表面描画、同期対象の判定、遮蔽情報への問い合わせを削減した。

## 変更内容

- 最大4灯をまとめて表面描画し、共通の形状のラスタライズとテクスチャ参照を減らす。各灯の色・強さ・減衰・上限・影は個別に計算する。
- 1024×1024の影、最大128枚・512MiBの深度キャッシュ、64MiBの共有形状上限を維持。動く照明の影を間引かない。
- 同じtick内の照明変更を区画ごとに集約し、同期対象の判定を繰り返さない。明るさだけの変更では、区画内の照明候補を再走査しない。
- バニラと同じ光線の通過順・端点の補正・同時に面を横切る際の順序を保ち、空の4×4×4領域・16×16×16区画でブロック情報への問い合わせを省く。特殊形状の交差判定は従来どおり。
- 区画ごとの16灯分という遮蔽キャッシュの制限を撤廃し、全体8,192組・ビット配列8MiBの上限を共有する。よく使われる結果を優先し、破棄された区画の結果も解放する。
- 前回追加した空間走査用の補助キャッシュを置き換え、重複する走査と保持するオブジェクトを減らす。

起動設定1280×720、VSync無効、上限260fps。比較前後ともプロファイラーを無効にし、全灯の設定と配置の署名を確認。

初回の実照度同期:

- 比較前: 設定確認から30秒後にも76区画が更新待ち。
- 変更後: 設定確認から30秒後の計測で更新待ち0。

5秒間隔のログによる確認であり、厳密な処理開始からの所要時間ではない。初回の広域計算には、引き続き数十秒かかる場合がある。

8灯単位も比較したが、この環境では4灯単位の方が速かったため4灯を採用した。
静止中と首振り中の負荷は異なる。64灯の首振りでは、4灯案の検証でview=1のフレーム中央値17.606ms、毎フレーム64枚の影更新を維持した。可動照明の影の再計算負荷は残る。
129灯以上では全灯分の影を保持できず、再計算が増えるという上限も維持している。

絶対値はこの試験環境の測定結果で、ユーザーのワールドの速度を保証しない。全modの特殊形状、独自ブロックエンティティ描画、Iris、Sable構造物を網羅した比較ではない。

## 品質・機能の検証

- ユニットテスト 78 件、失敗 0・エラー 0・スキップ 0。
- 光線の走査順2,500例と、空領域を含む遮蔽4,000例をバニラと照合。
- 鉄格子・フェンス・上下ハーフブロック・階段の遮蔽を、従来処理の3,000本の光線と照合して一致。
- 描画・照度102チェック、失敗0。点灯・消灯後の同期データは区画の4,096ブロック全てでサーバーと照合。フェード・色・遮蔽物・向き・ModelData変更、Flywheel、資源の再読込と解放も確認。
- 光源から床まで256ブロックの描画8チェック、失敗0。
- 64灯の色と強さを変え、従来の独立した1灯用シェーダーと新方式を3視点のRGBA32Fバッファで照合。各視点3,680,640成分、全視点で許容誤差を超える差0、OpenGLエラー0。最大絶対差 0.000055313。

画素比較の許容誤差は `0.0001 + abs(reference) * 0.00002`。カメラの座標基準を揃えて加算照明を比較する。通常の固定精度フレームバッファでの丸めを含む、ビット単位の画像一致を保証するものではない。

## 再現

```bash
mc-debug ./gradlew --no-daemon -PgpuDemo -PgpuMode=production -PgpuPerf -PgpuLights=128 -PgpuRange=256 runClient
mc-debug ./gradlew --no-daemon -PgpuDemo -PgpuMode=production -PgpuPerf -PgpuLights=64 -PgpuRange=256 -PgpuMotion=1 runClient

mc-debug ./gradlew --no-daemon -PproductionDemo runClient
```

画素比較用の `gpuCheck` は通常の速度比較とは別に実行する。比較用コードとシェーダーは通常JARには含めない。
